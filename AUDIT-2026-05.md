# Rich Statistics — Commercial Readiness Audit (May 2026)

**Date:** 2026-05-13
**Scope:** Full platform audit — plugin, PWA, Tauri desktop, CI/CD, documentation
**Goal:** Identify and resolve all issues before commercial launch

## 🔴 Critical — Must Fix Before Launch

### C1. `update.json` signatures empty across all environments
- **Location:** All three environments (`app`, `dev`, `test`)
- **Impact:** Tauri auto-updater rejects unsigned updates — desktop users permanently stuck
- **Root cause:** `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_KEY_PASSWORD` GitHub secrets not configured
- **Fix:** Add secrets to GitHub repo → push v2.4.1 tag → CI generates `.sig` files → `rsa-gen-update-json` populates signatures
- **Status:** ⏳ Requires GitHub secrets configuration (manual)

### C2. `SECURITY.md` capability check outdated
- **Location:** `SECURITY.md:45`
- **Current:** "All admin actions require `manage_options` capability"
- **Reality:** Plugin uses `rsa_manage_statistics` throughout
- **Impact:** Security auditors / WordPress.org reviewers will flag discrepancy
- **Fix:** Update text to `rsa_manage_statistics`
- **Status:** ✅ Fixed

### C3. `SECURITY.md` supported versions wrong
- **Location:** `SECURITY.md:7`
- **Current:** "1.x (current) | ✅ Active"
- **Reality:** Plugin is at 2.4.0 with 23 version entries
- **Fix:** Update to show 2.x as current, 1.x as EOL
- **Status:** ✅ Fixed

### C4. Freemius public key exposure
- **Location:** `rich-statistics.php:99-106`
- **Finding:** `public_key` and `wp_org_gatekeeper` visible in source
- **Assessment:** Freemius docs confirm public keys are safe in public repos. Gatekeeper string is a one-way hash for WordPress.org compliance.
- **Status:** ℹ️ Verified safe — no action needed

### C5. CSV export escaping incomplete
- **Location:** `includes/class-analytics.php:1214`, `includes/class-admin.php:807`
- **Current:** Uses `str_replace('"', '""', ...)` — does not handle newlines or commas within field values
- **Impact:** Page paths like `/page,"with,commas"` break CSV parsing in Excel/Google Sheets
- **Fix:** Use `fputcsv()` to a string buffer for proper RFC 4180 compliance
- **Status:** ✅ Fixed

## 🟡 High — Should Fix

### H6. No PHP 8.4 test coverage
- **Location:** `.github/workflows/tests.yml`
- **Current matrix:** PHP 8.1, 8.2, 8.3
- **Impact:** WordPress 6.9+ increasingly runs on PHP 8.4
- **Fix:** Add `'8.4'` to unit and integration test matrices
- **Status:** ✅ Fixed

### H7. `SCHEMA_VERSION` is stale
- **Location:** `includes/class-db.php:14`
- **Current:** `const SCHEMA_VERSION = 1;`
- **Reality:** Multiple schema changes across versions (wc_events table, etc.)
- **Impact:** No migration path detection — `dbDelta()` handles it additively but version tracking is broken
- **Fix:** Bump to match actual schema state, add migration logic for future changes
- **Status:** ⏳ Deferred — `dbDelta()` handles additive changes safely; schedule for v2.5.0

### H8. Dead code: `handle_site_config()` and `issue_token()`
- **Location:** `includes/class-pwa-download.php:99-159`
- **Finding:** Methods exist but never hooked to any action. `.rsasite` file download replaced by OTP flow.
- **Fix:** Remove dead code
- **Status:** ✅ Fixed

### H9. `export_events()` vs `export_data()` duplication
- **Location:** `includes/class-analytics.php:1109` and `includes/class-analytics.php:1147`
- **Finding:** Two separate export functions with overlapping logic, slightly different CSV formats
- **Impact:** Maintenance burden, inconsistency risk
- **Fix:** Consolidate into one function
- **Status:** ⏳ Deferred — low risk, schedule for v2.5.0 refactoring

### H10. `handle_test_send()` capability mismatch
- **Location:** `includes/class-email.php:138`
- **Current:** Uses `manage_options`
- **Should be:** `rsa_manage_statistics` for consistency
- **Status:** ✅ Fixed

### H11. Node.js 20 deprecation in CI
- **Location:** All workflow files
- **Finding:** GitHub runners moving to Node.js 22. Actions are current but verify compatibility.
- **Assessment:** `actions/checkout@v4`, `upload-artifact@v4`, `webfactory/ssh-agent@v0.9.0` all support Node 22. No action needed now.
- **Status:** ℹ️ Monitor — no immediate action

### H12. `bot_threshold()` default mismatch
- **Location:** `includes/class-analytics.php:1328` (default `3`) vs `includes/class-db.php:195` (seed default `5`)
- **Impact:** New installs get threshold 5, but `bot_threshold()` falls back to 3 if option is missing. Inconsistent behavior.
- **Fix:** Align both to `5` (the intended seed default)
- **Status:** ✅ Fixed

### H13. `fill_date_gaps()` timezone inconsistency
- **Location:** `includes/class-analytics.php:1244`
- **Current:** Uses `gmdate()` (UTC) while `period_range()` uses `current_time('timestamp')` (WordPress local time)
- **Impact:** Date gaps may be filled incorrectly for sites not in UTC timezone
- **Fix:** Use `wp_date()` consistently with WordPress local time
- **Status:** ✅ Fixed
